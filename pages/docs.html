Install

OpenBubble is distributed as a single static binary. The install script places it in ~/.local/bin on Linux/macOS or %LOCALAPPDATA%\Programs\OpenBubble on Windows.

curl -fsSL https://openbubble-ai.github.io/install.sh | bash

Other install methods:

npm i -g openbubble-ai@latest
bun add -g openbubble-ai@latest
brew install OpenBubble
paru -S openbubble-bin

Verify the installation:

OpenBubble --version
# OpenBubble 0.4.0

Quickstart

From any project directory, run:

cd my-project
OpenBubble

On first run, OpenBubble will ask you to pick a model provider. The free tier uses Models.dev included models — no account required.

Useful slash commands:

  • /help — list all commands
  • /model — switch the active model
  • /share — copy a share link to the current session
  • /clear — reset the conversation
  • /exit — quit

Providers

OpenBubble works with any LLM provider that exposes an OpenAI-compatible API. 75+ providers are preconfigured through Models.dev.

To connect a provider, set its API key in your environment or in the config file:

export OPENAI_API_KEY=sk-...
export ANTHROPIC_API_KEY=sk-ant-...
export GOOGLE_GENERATIVE_AI_API_KEY=...

You can also log in interactively with /login openai or /login github to use your existing ChatGPT or Copilot subscription.

Configuration

OpenBubble reads ~/.config/OpenBubble/config.json. A minimal config:

{
  "model": "anthropic/claude-sonnet-4",
  "theme": "system",
  "share": "manual",
  "lsp": {
    "auto": true
  }
}

Field reference:

  • model — default model in provider/model form.
  • theme — light, dark, or system (follow OS).
  • share — auto, manual, or off.
  • lsp.auto — automatically detect and load LSPs from the project.

Keybindings

OpenBubble follows standard terminal conventions. A few worth knowing:

  • Ctrl + C — cancel the current generation
  • Ctrl + L — clear the screen
  • Ctrl + R — reverse search history
  • ↑ / ↓ — navigate prompt history
  • / — open the command palette
  • Esc Esc — archive the current session

LSP

OpenBubble auto-detects Language Server Protocol servers for the languages used in your project. If a server is already on your $PATH, OpenBubble will use it. Otherwise it will install it via your package manager.

Disable specific servers in your config:

{
  "lsp": {
    "disabled": ["php"]
  }
}

Privacy

OpenBubble does not store your code, prompts, or session data. All communication happens directly between your machine and the model provider you configured.

For sensitive environments, run with --privacy to disable all telemetry and any background network calls:

OpenBubble --privacy

Enterprise

For self-hosted deployments, OpenBubble supports a fully air-gapped mode with a local model server (Ollama, vLLM, or LM Studio). Point OpenBubble at your local endpoint:

{
  "provider": {
    "name": "internal",
    "baseURL": "https://llm.internal.acme.corp/v1",
    "apiKey": "env:INTERNAL_LLM_KEY"
  }
}

Contact enterprise@openbubble.ai for SSO, audit logging, and custom SLAs.
